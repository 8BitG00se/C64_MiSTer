# OCTOPHONIC 64 - OLD-SOFTWARE REGRESSION TEST (Fix 69): THE LIST OF EVERYTHING WE RUN
# (c) 2026 Mong00se
#
# Every program here is run on the last core and on the new core (in the Octophonic 64 emulator, with
# the current KERNAL) and the pictures and sound are compared. The new core does not ship until every
# entry that can run comes out the same. See README.md.
#
# One entry a line, fields split by "|":
#   id | where | find | run | frames | input | needs | what it is
#
#   where  REPO   find = the file, a path inside this repo (committed .prg/.d64)
#          BUILT  find = the .asm source in this repo; regress.py assembles it with acme first
#          OB     find = a path inside the octophonic-backgrounds repo (OCTO_OB_REPO)
#          LOCAL  a finished build that lives in Neal's demo folders, not in git: find = its folder name,
#                 looked up under the folders in OCTO_BUILDS (on this machine: the session's scratchpad;
#                 on Neal's side: the d64 folder / C:\Octophonic\Demos copies). Missing -> skipped, said so.
#          NEAL   a stock C64 classic. NONE of these are in the repo and none may be added or downloaded:
#                 Neal supplies his own copies in the folder NEAL_GAMES. Missing -> skipped, said so.
#   find/run  run = the file inside that folder that is dropped on Octophonic OS ("-" = find is the file)
#   frames    how long it runs, in emulator frames (19656 cycles each; 1000 = about 20 seconds)
#   input     "-" or scripted input: JOY=frame:value,... (bits 1 up 2 down 4 left 8 right 16 fire, port 2)
#             or KEYS=frame:row:col,... (the emulator's OCTO_JOY / OCTO_KEYS)
#   needs     what the program uses (for the reader; "rtl" = also runs in the whole-C64 Verilator sim)
#
# Every program is dropped on Octophonic OS at frame 150, as a user would pick it in the browser. A .d64 is only
# mounted by that (as on the core), so for a .d64 with input "-" the runner presses F3 (LOAD) at frame 170:
# LOAD"*",8,1 and RUN, as Neal does on the start screen. Disk loading is the slow stock 1541 speed (no fast
# loader yet, Fix 49), so disk entries get long runs (Dithering Doughnut: 202 blocks, about 2 minutes).
